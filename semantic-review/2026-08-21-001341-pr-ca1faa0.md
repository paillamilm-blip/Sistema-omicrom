# Jarvis Presence System integration across all 9 feature modules

This commit wires the Jarvis Presence System (LivePulseBar, spatial audio, EmotionProvider, AuraBackground, SmoothNumber) into every feature module. Audio cues fire on user actions (quiz pass, job application, dispute open, navigation, text input), the pulse bar flashes to signal system aliveness, SmoothNumber animates the wallet balance, and AuraBackground renders behind the Gemelo profile header. The EmotionProvider wraps the entire app tree to inject CSS custom properties for ambient mood shifts.

Watch for: **Dead imports in 7 of 9 files** — `audioTick`, `audioPing`, `firePulse`, `SmoothNumber`, and `audioConfirm` are imported but never called in ChatTab, MarketTab, GemeloTab, AcademiaTab, GobernanzaTab, EmpleosTab, and OrbShell (confirmed). The `usePulseBar` hook in AppShell causes the entire shell subtree (including OrbShell) to re-render on every pulse fire — because nothing in the tree is memoized (likely performance drag on low-end mobile).

**Verdict**: NEEDS_CHANGES

## High-level view

The commit imports audio/pulse symbols into 7 modules where they're never invoked. Eight unused imports constitute dead code that signals the integration is incomplete: the author likely intended to add `audioTick` to buttons in Chat, Market, Gobernanza, and Empleos but stopped at the import line. This is either unfinished work or copy-paste residue — either way it should be cleaned before merge.

The `usePulseBar` architecture places state at the AppShell level with no memoization boundary, meaning every `firePulse()` triggers a full subtree re-render (OrbShell is 1200+ lines with many child components). On budget Android devices this may produce a perceptible frame drop. The alternative — hoisting `usePulseBar` into a dedicated narrow provider or wrapping OrbShell in `React.memo` — would isolate the blast radius.

All wired audio/pulse calls are correctly placed inside event handlers and post-async-success paths — never in effects or render bodies. No infinite re-render risk. JSX nesting in App.tsx is balanced, `SmoothNumber` in WalletTab receives a guaranteed `number`, and `AuraBackground` in GemeloTab receives a valid `AuraAxes` object. The commit will deploy to Vercel without build failures (`noUnusedLocals: false` in tsconfig, no new deps, no new env vars).

## usePulseBar re-render propagation

```
AppShell (owns pulseState via usePulseBar)
 └─ LivePulseBar ← receives state prop
 └─ OrbShell ← re-renders when pulseState changes
 └─ LiveNetworkFeed ← re-renders
 └─ IncomingJobPush ← re-renders
```

Every `firePulse('success')` call mutates `pulseState` from `'calm'` → `'success'`, triggering one AppShell render. This is not an infinite loop (confirmed) because `firePulse` is only called from event handlers. But OrbShell (~1200 LOC, 50+ state variables, multiple effects) absorbing unnecessary re-renders is a performance anti-pattern on constrained devices. The fix is either `React.memo(OrbShell)` or moving `usePulseBar` into a context that only wraps `LivePulseBar`.
