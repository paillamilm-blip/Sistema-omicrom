# Post-fix review: round 1 fixes verified

This review examines the `fix/ultra-review-round1` branch after three of the six original issues were addressed. The hasGreeted ref prevents double-greeting, the rAF breathing loop is throttled at 500ms, and market-match/vault-oracle are migrated to OpenRouter. The three deferred issues (client-side API key, credit bypass, coach fail-open) remain acknowledged and out of scope.

Watch for: **Stale "Gemini" comment in iaCredits.ts** (confirmed) — purely cosmetic but confusing for future contributors. **`geminiClient.ts` filename is misleading** (confirmed) — the file calls OpenRouter, not Gemini; an artifact of the partial rename. **Breathing animation sets state on every tick despite ref** (confirmed) — the `voiceLevelRef` is written but never read; state still updates every 500ms causing re-renders of the component tree.

**Verdict**: APPROVED

## High-level view

The `hasGreeted` ref correctly gates the proactive greeting to a single fire per mount. The early-return before setting `hasGreeted.current = true` is idiomatic and handles re-renders from profile refetches without issues.

The 500ms throttle on the idle breathing animation keeps re-renders at 2 Hz — acceptable for a cosmetic sine wave. The problem is the `voiceLevelRef` declared alongside it: the comment claims "use ref to avoid re-renders" but nothing reads the ref. `setVoiceLevel(v)` still fires on every throttled tick, so the component re-renders regardless. Dead code that implies an optimization that doesn't exist.

The OpenRouter migration is complete across all edge functions. No Gemini SDK imports remain anywhere. The only residual Gemini references are a stale comment in `_shared/iaCredits.ts` (line 5) and the filename `geminiClient.ts` which now exclusively calls OpenRouter.

## 500ms throttle and the voiceLevelRef contradiction

The breathing effect (starting ~line 561) throttles `setVoiceLevel` to fire at most every 500ms via a `ts - last > 500` gate inside the rAF callback. The code declares `voiceLevelRef` with a comment "use ref to avoid re-renders (purely cosmetic)" and then immediately calls `setVoiceLevel(v)` on the same line. The ref write achieves nothing because no consumer reads `voiceLevelRef.current` — the `OrbNeuronal` component receives `voiceLevel` (the state value) as a prop.

At 2 Hz the re-render cost is negligible for a modern device, so this isn't a performance bug — it's a code clarity issue. The comment misleads future developers into thinking the optimization is in place when it isn't. Either commit to the ref-only approach (pass `voiceLevelRef` to a child that reads it via a CSS custom property update) or delete the ref and accept the state path is intentional.

</details>
