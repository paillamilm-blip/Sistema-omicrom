# Visual overhaul: DNA helix, helical node orbit, BottomNav, and realtime subscriptions

This change replaces the particle sphere with a DNA double-helix canvas animation, restructures the draggable node orbit from a flat elliptical ring to a vertical helical distribution, introduces a 6-hub bottom navigation bar, removes the dead `gsap` dependency, unifies the design system into a single `theme.ts` source of truth (deleting `design-system/`), and adds Supabase realtime subscriptions to EmpleosTab and MarketTab. The approach is additive — the visual layer gets substantially richer while the data/auth layer stays untouched. Watch for: per-frame allocation in the helix renderer creating GC pressure on low-end phones (confirmed), `setRot` calling setState on every animation frame triggering React reconciliation across the entire node tree (confirmed), and the BottomNav always rendering even when the comment says "visible in todos los tabs excepto home" (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The ParticleOrb rewrite moves from a Fibonacci-sphere projection (~1600 points) to a DNA helix (120 per strand + 120 bridge dots + 200 floaters = ~580 drawn items), but each frame allocates a fresh `points[]` array plus one projected object per point, sorts them, then filters for strand trails. On a 60 fps loop this means ~580 short-lived objects and a sort every 16 ms with no object pooling, which will produce visible GC jank on mid-range mobile devices.

The NodeOrbit refactoring uses `setRot(...)` inside `requestAnimationFrame`, causing React to re-render the entire orbit tree (SVG lines + N motion.button nodes) at ~60 fps. The animation is purely visual positioning and should stay outside React state to avoid reconciliation overhead.

The BottomNav is always mounted in `AppShell` — there's no conditional hiding for the "Perfil" (home/OmicronAssistant) tab despite the comment indicating it should be hidden. Six hubs navigating to the first member of each hub means multi-member hubs (Perfil+Wallet, Academia+Habilidades, Mercado+Bóveda) have tabs reachable only from within that hub's screens, with no visible affordance to discover them.

Realtime subscriptions in MarketTab and EmpleosTab depend on the `load`/`loadServices` callback (which depends on `profile`), so the channel tears down and re-subscribes on every profile refresh — functionally correct but noisy and adds unnecessary reconnection latency.

<summary>Issues (5)</summary>

1. **Per-frame heap allocation in ParticleOrb** — The `draw()` loop creates a new `points[]` array (~580 objects) and `projected[]` array every frame, plus sorts and filters. Pre-allocate typed arrays or a fixed-size pool and mutate in place to eliminate GC pauses on mobile.
2. **setRot in rAF triggers full React re-render** — `NodeOrbit` calls `setRot(...)` inside `requestAnimationFrame`, reconciling the entire orbit (~9 motion.button + SVG) at 60 fps. Store rotation in a ref and apply it to DOM positions directly (or via a single CSS custom property / transform on the container).
3. **BottomNav visible on home tab despite comment** — The JSX comment says "visible en todos los tabs excepto home (OmicronAssistant)" but there is no conditional. Wrap in `{activeTab !== 'perfil' && <BottomNav />}` or conditionally hide with CSS if an exit animation is desired.
4. **Realtime re-subscribes on profile change** — The `useEffect` for realtime in both EmpleosTab and MarketTab depends on the `load`/`loadServices` callback, which depends on `profile`. Extract the channel setup into a separate effect with a stable dependency (ref-based pattern).

The zone decision and the node's visual resting position can disagree. Either disable momentum or commit the pin/anchor on animation settle instead of on pointer up.

## Per-frame allocation in the DNA renderer

Inside `ParticleOrb`'s `draw()` function (runs every animation frame):

```ts
const points: DrawPoint[] = [];
// ... 3 loops push ~580 objects ...
const projected = points.map(p => { ... });
projected.sort((a, b) => a.depth - b.depth);
// Then later:
const strandA = projected.filter(p => p.type === 'strandA').sort(...);
const strandB = projected.filter(p => p.type === 'strandB').sort(...);
```

Every 16 ms: one array of 580 objects, one mapped array of 580 projected objects, one sort, two filter+sort passes for trail drawing. This is ~1200 short-lived objects per frame. On a mid-range Android phone the minor GC pauses stack up and produce frame drops, especially because `globalCompositeOperation = 'lighter'` already taxes the canvas compositor.

The fix is to pre-allocate a single `Float32Array` (or a reusable object pool) sized to the maximum point count during the `useEffect` initialization, then write positions into it each frame without creating new objects. The sort can use index-based swapping on a pre-allocated index array.

## React state-driven animation in NodeOrbit

```ts
useEffect(() => {
  let raf = 0, last = performance.now();
  const loop = (t: number) => {
    const dt = Math.min(t - last, 64);
    last = t;
    setRot((r) => (r + dt * 0.00008) % (Math.PI * 2));
    raf = requestAnimationFrame(loop);
  };
  raf = requestAnimationFrame(loop);
  return () => cancelAnimationFrame(raf);
}, []);
```

`setRot` on every frame forces React to diff and reconcile the entire NodeOrbit subtree — the SVG with N `<line>` elements, plus N `motion.button` components each with complex inline styles computing positions from `rot`. Framer Motion then applies spring interpolation on top. This should be a ref:

```ts
const rotRef = useRef(0);
// in loop: rotRef.current = (rotRef.current + dt * 0.00008) % (Math.PI * 2);
// trigger a render only at ~20fps via a throttled setState or CSS variable update
```

Alternatively, move the orbit animation into a CSS custom property on the container and compute positions via CSS `calc()`.

## BottomNav always-visible mismatch

In `App.tsx`:

```tsx
{/* Navegación inferior — visible en todos los tabs excepto home (OmicronAssistant) */}
<BottomNav />
```

The comment promises conditional visibility, but the component renders unconditionally. On the "Perfil" tab the OmicronAssistant already occupies the full viewport with its own orbit UI; rendering BottomNav below it competes for vertical space. The fix:

```tsx
{activeTab !== 'perfil' && <BottomNav />}
```

## Realtime subscription lifecycle

Both EmpleosTab and MarketTab:

```ts
useEffect(() => {
  const channel = supabase
    .channel('empleos-realtime')
    .on('postgres_changes', { event: 'INSERT', ... }, () => { void load(); })
    .on('postgres_changes', { event: 'UPDATE', ... }, () => { void load(); })
    .subscribe();
  return () => { void supabase.removeChannel(channel); };
}, [load]);
```

`load` is a `useCallback` depending on `profile`. Every `refreshProfile()` call changes `profile` identity → `load` changes → channel unsubscribes/re-subscribes. A stable pattern:

```ts
const loadRef = useRef(load);
loadRef.current = load;

useEffect(() => {
  const channel = supabase
    .channel('empleos-realtime')
    .on('postgres_changes', ..., () => { void loadRef.current(); })
    .subscribe();
  return () => { void supabase.removeChannel(channel); };
}, []); // stable — never re-subscribes
```

## Drag momentum and position capture

The change enables `dragMomentum` (previously `false`) and adds `dragElastic: 0.15`:

```ts
drag
dragMomentum
dragElastic={0.15}
dragTransition={{ bounceStiffness: 300, bounceDamping: 25 }}
dragConstraints={containerRef}
```

In `onDragEnd`, the code reads `info.point` (the pointer position at release) to decide which zone the node landed in:

```ts
const py = ((info.point.y - containerRect.top) / containerRect.height) * 100;
const px = ((info.point.x - containerRect.left) / containerRect.width) * 100;
```

With momentum enabled, the node continues animating after the pointer lifts. `info.point` captures where the finger left the screen, not where the node will eventually settle. A fast upward flick releasing inside the anchor zone will anchor the node logically, but momentum will visually carry it above the zone before the spring pulls it back — visual and logical positions momentarily disagree. Either disable momentum (previous behavior), or use `onAnimationComplete` to read the node's resting position and only then commit the pin/anchor.
