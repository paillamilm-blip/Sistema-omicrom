# Merge perfil/ into gemelo/ — establishing the 2-concept architecture

This PR consolidates the scattered `features/perfil/` module entirely into `features/gemelo/`, reducing the conceptual surface from three overlapping modules (omicron + perfil + gemelo) to two with unambiguous responsibilities: Ómicron is the active coach that pushes the user, Gemelo is the passive identity layer that measures them. The circular dependency between gemelo and omicron is broken by extracting `levelInfo` and `nodeGuidance` into `shared/utils/guidance.ts` — two pure functions with zero feature-module imports. All import paths across 30+ files are updated, old paths are fully removed, and `features/perfil/` no longer exists on disk.

Watch for: Two stale documentation references in `DEFINICION_REPUTACION_OMICROM.md` still point to the deleted `reputationService.ts` filename without its new path (confirmed). The `preload.ts` dynamic import path (`import('@/features/gemelo/components/GemeloTab')`) resolves the default export via `.then(m => ({ default: m.GemeloTab }))` in `OrbShell` but does *not* use that wrapper in `preload.ts` itself — this is fine for preloading (the chunk just needs to be fetched, not mounted), but inconsistent naming could confuse future maintainers (possible).

**Verdict**: APPROVED

---

## High-level view

The circular dependency is cleanly severed. `shared/utils/guidance.ts` imports only from `@/types` and exports two pure functions. Both gemelo's `Guidance.tsx` and omicron's `coach.ts` consume from this neutral location, and `coach.ts` re-exports the symbols so existing consumers of `nodeGuidance` via `@/features/omicron/services/coach` continue to resolve without code changes. The dependency graph is now unidirectional: omicron → shared ← gemelo, with no gemelo → omicron service-level edges.

The `TabId` value `'perfil'` is deliberately preserved at the routing layer — `OrbShell` maps `case 'perfil'` to `<GemeloTab />`, `preload.ts` maps `perfil` to the GemeloTab chunk, and `HUB_NODES` keeps `tab: 'perfil'` for the "Mi ADN" hub node. Deep links, analytics events, and persisted `TabId` values in user state continue to work without migration.

The Vercel build is safe: zero source files reference the old `features/perfil` path or the deleted standalone paths (`@/hooks/useGemeloProfile`, `@/services/reputationService`). Every file referenced by an import in the diff exists on disk. `features/perfil/` is deleted cleanly with no orphaned barrel. The only build risk would be a pre-existing TypeScript error unrelated to this refactor.

The 2-concept model is properly established in code and documentation. Section 8 of `DEFINICION_OMICROM.md` documents the taxonomy, and the module boundaries match: `features/omicron/` contains coach/oráculo/voice/brain, `features/gemelo/` contains all identity/reputation/credentials/social/progress concerns.

## Circular dependency resolution

The previous cycle was: `gemelo/Guidance.tsx` → `omicron/services/coach.ts` (for `nodeGuidance`) while `omicron/OrbShell.tsx` → `gemelo/hooks/useGemeloProfile` and `gemelo/services/progressive` and `gemelo/services/proactive`. The fix extracts only the two leaf functions (`levelInfo`, `nodeGuidance`) that caused the back-edge into `shared/utils/guidance.ts`:

```typescript
// shared/utils/guidance.ts
import type { TabId, Profile, GemeloDigital } from '@/types';
export function levelInfo(pe: number) { ... }
export function nodeGuidance(tab: TabId, ...) { ... }
```

The re-export in `coach.ts` (`export { levelInfo, nodeGuidance } from '@/shared/utils/guidance'`) preserves backward compatibility for any consumer that imports these via `@/features/omicron/services/coach`.

Post-refactor dependency graph:

```
shared/utils/guidance.ts   (pure, types-only imports)
        ↑            ↑
   omicron/          gemelo/
   coach.ts          Guidance.tsx
   (re-exports)      (direct import)

omicron/OrbShell  →  gemelo/hooks/useGemeloProfile
                 →  gemelo/services/progressive
                 →  gemelo/services/proactive

gemelo/RedSocialTab  →  omicron/components/OmicronChrome  (layout primitives only)
```
