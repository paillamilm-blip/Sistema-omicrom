# Gemini-first LLM provider with browser TTS fallback (v3)

This change promotes Google Gemini (gemini-2.0-flash) as the primary LLM provider across all Supabase Edge Functions, with OpenRouter demoted to a 6-model fallback chain. A shared `_shared/llm.ts` module encapsulates the two-tier strategy (22s Gemini timeout, 25s per-model OpenRouter timeout, header-based API key auth) for 9 domain functions. `proxy-ai` keeps an inline Gemini path with its own 22s timeout, dead-model caching, and user-supplied parameter clamping. The frontend `voice.ts` gains a browser speechSynthesis fallback triggered by a 200 JSON signal from `proxy-tts` when all TTS models fail.

All 8 issues raised across the v1 and v2 review passes have been addressed: API key moved to header, timeouts added to both Gemini paths, `{ once: true }` on all abort listeners, dead temperature clamp removed, OpenRouter fallback expanded to 6 models in the shared module, and the backup file deleted.

Watch for: No new blocking concerns. The duplicated Gemini call logic between `_shared/llm.ts` and `proxy-ai` remains intentional technical debt — acceptable now, but a maintenance burden if the Gemini integration grows (confirmed, non-blocking).

**Verdict**: APPROVED

## High-level view

The shared LLM client gives 9 domain functions a zero-config Gemini upgrade: 22s timeout with immediate fallthrough to a 6-model OpenRouter chain (25s per model), API keys in headers, stateless and minimal.

`proxy-ai` keeps its own inline Gemini path because it handles user-supplied temperature/maxTokens with clamping, has dead-model caching for OpenRouter, and integrates credit-gating and rate-limiting. The duplication lets `proxy-ai` maintain richer error-handling semantics without coupling to the simpler shared module. If the Gemini integration grows (system instructions, safety settings), maintaining two implementations will become a burden.
