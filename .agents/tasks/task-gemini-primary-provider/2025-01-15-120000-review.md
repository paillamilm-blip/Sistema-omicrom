# Gemini-first LLM provider with browser TTS fallback

This change promotes Google Gemini (gemini-2.0-flash) as the primary LLM provider across all Supabase Edge Functions, with OpenRouter demoted to fallback. A new shared `_shared/llm.ts` module encapsulates the two-tier strategy for 9 domain functions, while `proxy-ai` gets its own inline Gemini-first path (it already had multi-model OpenRouter logic). Separately, `proxy-tts` now returns a 200 JSON signal instead of a 503 when all TTS models fail, and the frontend `voice.ts` detects this signal to fall back to the browser's Web Speech API.

Watch for: API key leaked in URL query parameter across all Gemini calls (confirmed). Abort listener accumulation in `speakWithBrowserTTS` — a new listener is registered on every chunk invocation without cleanup (confirmed). The `_shared/llm.ts` module has no request timeout, so a hanging Gemini request will block indefinitely (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The shared LLM client (`_shared/llm.ts`) gives 9 Edge Functions a zero-config upgrade path: swap the import from `openrouter.ts` to `llm.ts` and the function automatically tries Gemini first. It lacks the timeout and dead-model caching that `proxy-ai` already implements for OpenRouter, making it less resilient under transient Gemini outages.

`proxy-ai` duplicates the Gemini call logic inline rather than importing from `_shared/llm.ts`, resulting in two implementations with subtly different behavior (e.g., `proxy-ai` caps `maxOutputTokens` at 4096 and clamps temperature; `_shared/llm.ts` does not).

The TTS fallback contract changed from "503 means failure, client stays silent" to "200 with `{ fallback: true, text }` means use browser speech." The abort-listener registration in `speakWithBrowserTTS` leaks event listeners across sentence chunks — each call adds a new `abort` listener that is never removed after the utterance finishes.

The Gemini API key is passed as a URL query parameter (`?key=GEMINI_KEY`) in every `fetch` call. Google supports the `x-goog-api-key` header as an alternative that keeps the key out of access logs, proxy logs, and error stack traces.

## Gemini API key exposure in URL

Both `_shared/llm.ts` and `proxy-ai/index.ts` pass the API key as a query parameter:

```typescript
const resp = await fetch(`${GEMINI_URL}?key=${GEMINI_KEY}`, { ... });
```

Google's Generative Language API supports the `x-goog-api-key` header as an alternative. Using the header keeps the key out of URL-based logging (access logs, CDN logs, error stack traces that include the request URL). In an Edge Function context the blast radius is small (the network hop is Deno → Google), but if any error-reporting middleware stringifies the request, the key will appear in plaintext.

## Missing timeout in shared LLM client

`proxy-ai` wraps its OpenRouter fetch in a 25-second AbortController. The shared `callGemini` function has no such guard:

```typescript
// _shared/llm.ts — no timeout
const resp = await fetch(`${GEMINI_URL}?key=${GEMINI_KEY}`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(body),
});
```

If Gemini accepts the TCP connection but stalls, the Edge Function will block until Supabase's global timeout kills it (default 60s in free tier). Adding an AbortController with a 20–25s timeout would let the function fall through to OpenRouter in a reasonable time.

## Abort listener leak in browser TTS fallback

`speakWithBrowserTTS` registers an abort listener every time it's called:

```typescript
abortController?.signal.addEventListener('abort', () => {
  window.speechSynthesis.cancel();
  resolve();
});
```

The promise resolves via `onend` or `onerror` when the utterance finishes, but the abort listener remains attached to the signal. For a typical Ómicron response split into 5–15 chunks, that's 5–15 stale closures holding references to resolved promises. The listener array grows unbounded within a single `speakOmicron` call.

Fix: pass `{ once: true }` as the third argument to `addEventListener`, or store a reference and call `removeEventListener` in the cleanup paths.

## Divergent Gemini implementations

`proxy-ai` applies `Math.min(maxTokens, 4096)` and `Math.min(Math.max(temperature, 0), 1.5)` to clamp user-supplied values before sending them to Gemini. The shared `_shared/llm.ts` passes `maxTokens` unclamped and uses a hardcoded `temperature: 0.7`. If a caller of the shared module passes `maxTokens: 100000`, it goes straight to the Gemini API unchecked. The behavioral asymmetry means the same user action could behave differently depending on whether it hits `proxy-ai` or a domain function using the shared module.

## OpenRouter fallback depth asymmetry

The shared `_shared/llm.ts` tries exactly 2 OpenRouter models (`gemma-4-31b-it:free`, `gemma-4-26b-a4b-it:free`). `proxy-ai` tries 6 models with dead-model caching and per-model abort timeouts. If Gemini is having a bad day, the 9 domain functions will exhaust their fallback chain much faster than `proxy-ai`, surfacing "IA no disponible" errors while the proxy endpoint still works.

## Backup file left in tree

`openrouter.ts` was renamed to `openrouter.backup.ts` rather than deleted. It's no longer imported anywhere. Dead code in `_shared/` can confuse future contributors about which module to import. Either delete it or add a comment explaining the rollback intent.
