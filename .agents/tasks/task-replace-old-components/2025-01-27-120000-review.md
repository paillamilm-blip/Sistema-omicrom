# Ultra Review: Sistema Omicron Design System Overhaul (v1)

A ground-up replacement of the visual and interaction layer for a React+Vite+TypeScript PWA. The old Three.js ParticleOrb, SuggestionChips, and CyberComponents' ScanlineOverlay are removed. In their place: a lightweight SVG GeodesicOrb for loading states, a rewritten Three.js OrbNeuronal (geodesic wireframe with touch rotation), a shared OmicronChrome design system, a motion library on framer-motion, spatial audio via Web Audio API, haptic feedback, user-selectable accent colors, an EmotionBridge ambient system, and a self-managed LivePulseBar. Architecturally, `features/perfil/` is merged into `features/gemelo/` with a clean two-concept model (Ómicron = coach, Gemelo = identity), and the circular dependency is broken by extracting pure functions into `shared/utils/guidance.ts`.

Watch for: Two new files ship with `@ts-nocheck` (OrbNeuronal, ProactiveCards) — meaning they bypass type safety entirely in ~1340 lines of complex rendering code (confirmed). The `OmicronChrome` module evaluates `getUserColor()` at *module load time* to compute the static `S.actionBtn` style, so a runtime color change requires a page reload to reflect in button gradients (confirmed). The `omicronAudio` singleton's `AudioContext` is created on first call to `init()` but never closed — acceptable for a long-lived SPA, but a resource leak in test environments (likely).

**Verdict**: APPROVED

---

## High-level view

The ParticleOrb removal is thorough: all three files deleted, every import site migrated to GeodesicOrb (SVG) or OrbNeuronal (Three.js). OrbNeuronal is completely rewritten from a particle system to a geodesic wireframe, with pointer-drag rotation using lerp-target separation for smooth motion. The `@ts-nocheck` pragmas on OrbNeuronal and ProactiveCards suppress an unknown number of type issues — any runtime type error in these files will surface as a user-facing crash with no compile-time warning. This is the single biggest quality gap in the changeset.

The module restructure collapses `features/perfil/` into `features/gemelo/`. The preserved `TabId = 'perfil'` routing value means deep links, analytics events, and persisted state continue to work without migration. The circular dependency (gemelo → omicron → gemelo) is eliminated by `shared/utils/guidance.ts`; `coach.ts` re-exports the functions for backward compatibility.

The motion library (14 components) and ambient systems (LivePulseBar, EmotionBridge, spatialAudio, haptics) form a feedback layer triggered by user actions. The pattern `audioPing(); firePulse('success')` is fire-and-forget, backed by module-level singletons. If `firePulse` is called before `SelfManagedPulseBar` mounts, the call is silently dropped — acceptable given mount ordering in `AppShell`.

The `getUserColor()` module-scope evaluation in `OmicronChrome.tsx` creates a stale-value bug: `S.actionBtn.background` is computed once at import time. The `OmicronHeader` component handles this correctly (reads at render time via the `accent` default param), but the `OmicronAction` button renders the old color until page reload.

## OrbNeuronal: @ts-nocheck in 1052 lines of Three.js

The rewrite constructs an icosahedron with `THREE.IcosahedronGeometry(radius, subdiv)`, extracts unique vertices from the wireframe edge geometry, and renders them as `THREE.Points` with a canvas-generated radial gradient texture. Hub node positions are distributed via Fibonacci sphere for raycasting. Touch rotation uses dual `targetRotation` / `currentRotation` values with lerp interpolation and velocity decay (`*= 0.97`).

The `@ts-nocheck` at line 1 blankets all of this. The Three.js code uses `any` casts on raycaster and material properties that could be resolved with proper type assertions (`as THREE.Mesh`, `as THREE.PointsMaterial`). Removing the pragma and fixing individual lines is the correct path — the alternative is silent runtime crashes in production with no build-time signal.

## ColorPicker module-scope stale value

```typescript
// OmicronChrome.tsx — computed ONCE at import time
const S: Record<string, CSSProperties> = {
  actionBtn: {
    background: `linear-gradient(135deg,${getUserColor()},#5e5ce6)`,
    boxShadow: `0 8px 20px rgba(10,132,255,0.34)`,
  },
};
```

Every `<OmicronAction>` in the app (Market "Publicar", Empleos filter, Vault actions) renders this stale gradient. The user picks a new color during onboarding via `setUserColor()` → localStorage. On the *same* session where onboarding runs, `OmicronChrome` was already imported (it's used by `OrbShell`), so buttons keep the old color until the next page load. Fix: make `actionBtn` a function or use a CSS variable.

## LivePulseBar: silent drop before mount

`firePulse()` calls `_setState?.(s)` where `_setState` is registered in `SelfManagedPulseBar`'s `useEffect`. If any code fires a pulse during the synchronous render phase (before effects run), the call no-ops. In the current code this doesn't happen — all `firePulse` calls are in event handlers or async callbacks — but it's a latent trap for future callers.

## EmotionBridge sessionStorage

```typescript
useEffect(() => {
  if (!profile) return;
  const pe = profile.pe_points ?? 0;
  if (pe > 0) sessionStorage.setItem('omicron_session_pe', String(pe));
  // ...
}, [profile?.pe_points, profile]);
```

No guard against `sessionStorage` being undefined. The SPA is currently client-only, but if Vercel's build process ever pre-renders this path (e.g., ISR), it would throw `ReferenceError: sessionStorage is not defined`.
