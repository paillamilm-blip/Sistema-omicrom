# AI pipeline bug fixes: timeout, CORS, guest access, and unknown-intent routing

Seven bugs prevented AI from responding to users. The fixes address a non-functional client timeout (Promise.race replacing the never-wired AbortController), CORS headers computed at module level without access to the request, a credit check that rejected unauthenticated guests, a hardcoded model name mismatch, the OraculoBar voice path silently dropping unknown intents instead of routing them to the AI brain, the brain fallback not signaling error state, and a Gemini timeout bumped from 22s to 25s for cold-start resilience. The test for "hola" was updated to expect `unknown` since it's now routed to AI rather than matched as a help command.

Watch for: **Mutable module-level CORS variable** creates a race condition under concurrent requests (confirmed). **Client timeout (20s) shorter than server timeout (25s)** means the client will discard responses that the server is still generating (confirmed). **Guest auth bypass** allows unlimited unauthenticated AI usage gated only by IP rate limit (confirmed). **`gemini-3.6-flash` is not a known Gemini model** — if this is a typo or placeholder, the Gemini path will 404 every time and silently fall through to OpenRouter (possible).

**Verdict**: NEEDS_CHANGES

## High-level view

The client timeout was dead code: AbortController was never passed to `supabase.functions.invoke()`, which doesn't accept signals. The fix uses `Promise.race` against a timeout promise that resolves with an error shape — simple, correct, and works with the existing null-return contract. However, `brain.ts` passes `timeout: 20000` while the edge function gives Gemini 25s, so the client will always time out on a slow Gemini cold start and throw away the response the server eventually produces.

The CORS fix moves header computation into the request handler, but the new `let CORS` module-level variable is shared mutable state. In Deno's edge runtime, requests within the same isolate can interleave at `await` points. If two requests from different origins overlap, the second request's `CORS = corsHeaders(req)` overwrites the first's headers before the first finishes writing its response. This is the one structural bug introduced by the fix.

Removing "hola" from the ayuda regex and routing unknown intents to the AI brain is a good UX improvement — casual greetings now get a personalized AI response instead of a canned help string. The OraculoBar duplicates the exact same `askOmicron` call shape in two places (coach branch and unknown branch), which is cosmetic but worth extracting.

The guest bypass (`authHeader.trim() !== 'Bearer'`) lets any request without a JWT use the AI unlimited by credits. The only gate remaining is the 15-req/min IP rate limit. This might be intentional for a freemium model, but it means a single IP behind a NAT (office, university) shares that 15/min budget across all unauthenticated users hitting it.

## CORS: mutable module-level state under concurrency

The original bug was real — `corsHeaders()` was called at import time without a request, producing headers with the default production origin regardless of the actual caller. The fix moves computation into the handler:

```typescript
let CORS: Record<string, string> = {};
// ...
Deno.serve(async (req) => {
  CORS = corsHeaders(req);
  // ... multiple awaits before CORS is used in json() responses
});
```

The problem is that `CORS` is a single module-level binding. Deno's edge runtime (and the Supabase variant) can process multiple requests concurrently within one isolate — they share the module scope. Between the assignment at line 86 and the eventual `json()` call after several `await` points (rate limit check, credit check, Gemini fetch, OpenRouter fetch), another request can overwrite `CORS`. The failure mode is a response with the wrong `Access-Control-Allow-Origin`, which the browser will reject as a CORS error.

Fix: make `CORS` a `const` local inside the handler and pass it to `json()`, or refactor `json()` to accept an origin parameter.

## Client-server timeout mismatch

```
brain.ts          → callAI(..., { timeout: 20000 })
  → client.ts    → Promise.race at 20000ms
    → proxy-ai   → Gemini fetch with AbortController at 25000ms
```

If Gemini takes 21s (common on cold starts), the client resolves the timeout promise, returns `null`, and the brain returns the offline fallback with `error: 'ai_unavailable'`. Meanwhile the edge function completes successfully — but nobody is listening. The user sees a fallback message, possibly followed by nothing. The 5s gap between client and server timeouts is the window where work is wasted.

The `callAI` default timeout is 30s, but `brain.ts` explicitly passes 20s. Either the brain timeout should be raised to ≥26s (to accommodate the server's 25s + network overhead), or the server's Gemini timeout should be lowered to ~18s to guarantee it resolves within the client window.

## Guest authentication bypass

```typescript
if (authHeader.trim() && authHeader.trim() !== 'Bearer') {
  const creditBlock = await checkAndConsumeCredit(_admin, authHeader, 'proxy-ai');
  if (creditBlock) return creditBlock;
}
```

This means:
- No `Authorization` header → skip credit check entirely
- `Authorization: Bearer` (token missing) → skip credit check
- `Authorization: Bearer <jwt>` → check credits

The only remaining protection for unauthenticated requests is the IP-based rate limit (15/min). A single script without auth headers can make 15 AI calls per minute indefinitely — 900/hour, 21,600/day — burning API credits on the provider side without any per-user throttle. Whether this is acceptable depends on the product model, but it should be a deliberate documented decision.

## `gemini-3.6-flash` model validity

The diff changes the model from `gemini-2.0-flash` to `gemini-3.6-flash` in both `proxy-ai/index.ts` and `_shared/llm.ts`. As of mid-2025, publicly documented Gemini Flash models include `gemini-2.0-flash`, `gemini-2.5-flash`, and `gemini-1.5-flash`. `gemini-3.6-flash` does not appear in the Gemini API documentation or model garden. If this model doesn't exist on the Google endpoint, every Gemini request will fail with a 404, and the system silently falls through to OpenRouter free models (which is the correct fallback behavior, but defeats the purpose of making Gemini primary).

## OraculoBar: duplicated askOmicron call

The `coach` branch and the new `unknown` branch in `OraculoBar.tsx` construct identical context objects and make the same `askOmicron` call with the same post-processing (flash, speak with 320-char truncation, remember). The only differences: the flash preamble message ("Consultando al Coach IA…" vs "Déjame pensar…") and the memory metadata (`coachAdvice: true` vs `aiResponse: true`). This is minor but the duplication means future changes (e.g., adding error handling for `r.error`) need to be applied in two places within the same function.

## Missing error propagation to user

`brain.ts` now returns `{ text: fallback, error: 'ai_unavailable', toolCall: null }` when AI fails. None of the callers (OraculoBar, OrbShell, AcademiaTab, MaxSkillTab) check `r.error`. The fallback text is presented as if it were a normal AI response. This is arguably fine UX (the user gets *something*), but it means the UI cannot distinguish between an AI-generated response and a canned offline fallback — no retry prompt, no visual indicator, no degraded-mode styling. The `error` field was added but is currently dead code on the consumer side.

## Test coverage

The test file covers the `interpret()` regex engine comprehensively: empty inputs, navigation, convalidation, coach triggers, facts, and the updated "hola" expectation. The change from `{ kind: 'fact', topic: 'ayuda' }` to `{ kind: 'unknown' }` for "hola" correctly reflects the new routing.

Not tested: the `callAI` Promise.race timeout (would require mocking `supabase.functions.invoke` with a slow promise), the CORS computation, the guest auth bypass path, or the OraculoBar async behavior with `askOmicron`. The brain.ts `error: 'ai_unavailable'` addition has no test verifying it appears in the response when `callAI` returns null.
